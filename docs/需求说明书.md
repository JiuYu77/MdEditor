## 1. 项目概述

### 1.1 背景与动机

市面上的 Markdown 编辑器存在两类典型风格：

- **Typora 式**：所见即所得（WYSIWYG），界面极简、专注写作，但侧边栏/辅助功能较弱，且为闭源付费软件。
- **VS Code 式**：功能强大，左侧有文件树、搜索、扩展市场等丰富面板，但本质是通用代码编辑器，写作体验不如 Typora 沉浸。

本项目希望**取两者之长**：以 Typora 的简洁沉浸式写作体验为核心，融入 VS Code 式的左侧功能栏（文件树、搜索、大纲、扩展等），并在此基础上提供**高度可定制的主题系统**（含标题栏样式、是否无边框窗口），满足不同用户对界面外观的个性化需求。

### 1.2 产品定位

- **一句话定位**：一款跨平台的、极简但可扩展的所见即所得 Markdown 编辑器。
- **目标用户**：技术写作者、博客作者、学生、知识管理爱好者、程序员。
- **核心理念**：默认简洁，进阶可扩展；开箱即用，按需定制。

### 1.3 产品目标

| 目标 | 说明 |
| --- | --- |
| 写作体验对标 Typora | 实时渲染、光标跟随、沉浸模式、专注模式 |
| 功能组织对标 VS Code | 可折叠左侧活动栏 + 侧边栏，模块化、可扩展 |
| 主题深度可定制 | 支持自定义配色、字体、标题栏样式、无边框窗口 |
| 全平台一致体验 | Windows / macOS / Linux 三端功能与体验一致 |

### 1.4 非目标（本期不做）

- 不做多人实时协同编辑（可预留扩展点）。
- 不做完整 IDE 功能（调试、终端等）。
- **不内置官方云同步服务**——但支持用户接入**自己的服务器**做云同步（自带服务器 BYOS，见 §3.5.5）；官方不做云端账号体系，数据始终在用户自己手里。

## 2. 用户画像与使用场景

### 2.1 用户画像

| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| 技术博主 | 写技术文章、博客 | 实时预览、代码块高亮、图片管理 |
| 学生/研究者 | 记笔记、写论文 | 大纲导航、专注模式、主题护眼 |
| 程序员 | 写 README、技术文档 | 快速打开工程文件、Git 集成、快捷键 |
| 极客/外观控 | 追求个性化 | 深度主题定制、无边框窗口、标题栏自定义 |

### 2.2 核心使用场景

1. **沉浸写作**：全屏/专注模式下只保留编辑区，实时渲染 Markdown。
2. **工程文档管理**：从左侧文件树打开整个文档目录，跨文件检索。
3. **个人定制**：通过主题设置或导入主题文件，改变配色、字体、标题栏样式与窗口边框。
4. **跨设备迁移**：同一份文件在三平台打开，排版与交互一致。

#### 3.4.3 标题栏自定义（Title Bar）

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| TB-01 | 标题栏样式可切换 | P0 | 提供以下样式，切换即时生效 |
| TB-02 | 样式 A：系统原生标题栏 | P0 | 使用操作系统原生标题栏（最稳，无障碍性最好） |
| TB-03 | 样式 B：自定义标题栏 | P0 | 应用自绘标题栏：可设置背景色/透明、文字颜色、是否显示文档名（**默认显示，含未保存 ● 标记**）、图标 |
| TB-04 | 样式 C：隐藏标题栏（无边框） | P0 | 见 3.4.4 |
| TB-05 | 标题栏颜色可配置 | P0 | 自定义标题栏背景色与文字色，可设为与主题主色一致或跟随窗口背景 |
| TB-06 | 窗口控制按钮样式 | P1 | 最小化/最大化/关闭按钮可自定义（形状、颜色、悬停效果），或使用系统默认 |
| TB-07 | 双栏标题栏（预留） | P2 | 左侧放文件信息/面包屑，右侧放操作按钮 |

> **实现说明（Tauri 2）**：
> - 样式 A（原生）：`decorations: true`。Windows 原生标题栏颜色官方 API 不直接支持，需在 Rust `setup` 中通过 `windows` crate 调用 `DwmSetWindowAttribute`（`DWMWA_CAPTION_COLOR` / `DWMWA_TEXT_COLOR` / `DWMWA_BORDER_COLOR`）实现，**仅 Windows 11 22H2+ 有效**（详见 §6）。
> - 样式 B（自绘）：`decorations: false` + HTML/CSS 自绘标题栏；拖拽用 `data-tauri-drag-region` 或 `startDragging()`；控制按钮可用 `agmmnn/tauri-controls` 组件库（跨平台、含 macOS 红绿灯样式）。
> - 样式 C（无边框）：`decorations: false` + 隐藏控制按钮，进入全屏沉浸。
> - 三态切换为运行时动态切换：Tauri 支持运行时修改 `decorations`（部分平台需重建窗口，切换时需保留文档状态，见 FW-01 备注）。
>
> **标题栏 × 主题联动能力矩阵**（"软件 theme 能否改标题栏"）：
>
> | 标题栏模式 | Windows | macOS | Linux |
> | --- | --- | --- | --- |
> | 样式 A 原生 | ⚠️ 可改色，仅 **Win11 22H2+**（Rust 调 `DwmSetWindowAttribute`；每次切主题需前端→Rust 重新联动） | ⚠️ 仅随系统深浅色 / 红绿灯区域毛玻璃 | ❌ 不可控（X11 由 WM 绘制 SSD；GNOME CSD 行为不可靠） |
> | 样式 B 自绘 | ✅ 主题 100% 控制（CSS 变量，即时生效） | ✅ 主题 100% 控制 | ✅ 主题 100% 控制 |
> | 样式 C 无边框 | —（无标题栏） | —（无标题栏） | —（无标题栏） |
>
> **结论**："主题改标题栏"以**样式 B（自绘）为三平台一致的主路径**；样式 A 仅在 Windows 11 22H2+ 做可选增强，其余平台/低版本自动忽略（回退逻辑见 FW-06）。

#### 3.4.4 无边框窗口（Frameless Window）

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| FW-01 | 无边框开关 | P0 | 全局设置"无边框窗口"开关，切换后重启/即时生效（即时生效优先，见 FW-06） |
| FW-02 | 无边框下的拖拽移动 | P0 | 无边框时，可通过标题栏区域（或指定拖拽区）拖动窗口 |
| FW-03 | 无边框下的窗口控制 | P0 | 最小化/最大化/还原/关闭功能完整可用，含键盘快捷键（Win+方向键、macOS 绿色按钮） |
| FW-04 | 无边框下的贴边/分屏 | P1 | Windows 下支持 Aero Snap / Win11 Snap Layout（拖拽到屏幕边缘自动分屏、悬停显示布局面板） |
| FW-05 | 圆角与阴影 | P1 | 无边框时可配置窗口圆角与阴影（Windows 11 / macOS 效果最佳） |
| FW-06 | 平台差异处理 | P0 | macOS 保持红绿灯按钮可用与 Traffic Light 位置适配；Linux 各桌面环境（GNOME/KDE 等）需兼容处理 |

> **实现说明（Tauri 2）**：
> - **Snap Layout 是最大坑**：仅靠 `data-tauri-drag-region` 拖拽无法触发 Windows 11 Snap Layout 悬停面板，需借助社区插件（`tauri-plugin-decorum` 或 `tauri-plugin-decoration`，详见 §6）或按 [tauri#4531](https://github.com/tauri-apps/tauri/issues/4531) 的讨论方案实现。
> - macOS：Traffic Light 可通过官方 `titleBarStyle: Overlay`（透明/悬浮样式）或 `decorum` 插件实现。
> - 圆角/阴影：Windows 11 可用 `window-vibrancy` 的 Mica/Acrylic 效果顺带获得沉浸式标题栏；阴影可用 `window-shadows` 类方案或系统 DWM 阴影。

#### 3.4.5 主题包结构与格式（纯 CSS，文件夹形式）

> **决策**：主题采用**文件夹包结构**——一个主题 = 一个文件夹（`my-theme/`），内含入口 CSS 与可选资源目录。纯 CSS 承载样式（CSS 自定义属性 = 变量），不使用 JSON；文件夹形式使 CSS 可以**相对路径引用资源**（背景图、字体），这是单文件 CSS 无法做到的。

**主题包结构：**

```
my-theme/                    # 主题包：文件夹名即主题标识（显示名可用注释覆盖）
├── theme.css                # 【必选】主题入口：CSS 变量 + data-theme 作用域
├── other.css                # 【可选】附加样式（other.css / 任意命名的补充样式表）
└── res/                     # 【可选】资源目录：背景图、字体、图标等
    ├── bg.png
    └── font.woff2
```

**`theme.css` 示例：**

```css
/* 主题元信息：以注释形式携带（导入时展示名称，不参与渲染） */
/* name: My Theme */
/* type: light */          /* light | dark，用于图标/托盘/系统适配 */

/* 引入附加样式（可选，相对路径） */
@import "./other.css";

/* 自定义字体（可选，资源来自 res/） */

  src: url("./res/font.woff2") format("woff2");

/* 主题变量：覆盖在 :root 上，切换主题即切换生效的变量集合 */

  --font-code: "JetBrains Mono", monospace;
```

**规则与边界：**

1. **结构约定**：`theme.css` 必选，为入口；`res/` 与补充样式表（如 `other.css`）可选，通过 `@import` 或 `url()` 相对路径引用。
2. **相对路径解析**：CSS 内所有 `url()` 均**相对于 `theme.css` 所在目录**（即主题包根目录）解析——资源随包走，分享/迁移不丢资源。
3. **校验**：导入时校验 `theme.css` 存在 + CSS 语法解析（语法错误拒绝导入并提示行号）；**变量缺失自动回退到内置默认主题**，不阻断；引用的资源文件缺失 → 警告并回退占位，不阻断。
4. **主题切换 = 切换 `data-theme` 属性**：内置主题与导入主题统一为"主题包"形态，切换即时生效、无需重启（T-02）。
5. **作用域边界**：CSS 主题只管**视觉样式**；功能开关（无边框开关、标题栏三态模式 native/custom/frameless）属应用设置，不进主题包——但自绘模式下的视觉属性（背景/文字/透明/圆角）全部由 CSS 变量控制。
6. **CSS 变量体系**：内置变量清单即主题 API（上表），支持任意 CSS 语法深度定制（P1 高级用户可直接写原生 CSS）。
7. **导入方式**：将整个主题包文件夹放入主题目录（如 `~/.config/com.mdeditor.desktop/themes/`）即可被识别；或通过设置界面选择文件夹/压缩包导入。**导出** = 将当前自定义设置序列化为一个主题包（`theme.css` + `res/`）。

### 3.5 通用功能

#### 3.5.1 多标签与多窗口（融合方案）

> **产品决策**：采用"多标签为默认 + 自动隐藏"的融合方案——单文件时界面接近 Typora（无标签栏），打开第二个文件时标签栏自动出现，过渡到 VS Code 式多文件工作流。

**标签栏显示模式（设置项）：**

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| 自动（默认） | 单文件时隐藏标签栏；≥2 个文件时自动显示 | 写作与工程兼顾，推荐 |
| 始终显示 | 标签栏常驻 | 纯 VS Code 式多文件工作流 |
| 始终隐藏 | 标签栏不占空间，切换文件走 Ctrl+Tab / 文件树 / 命令面板 | 极致简洁 |

**标签栏交互：**
- 每个标签：文件名 + 修改标记（●）+ 关闭按钮；中键点击关闭；拖拽调整顺序；拖出可拆分为新窗口（P2 预留）。
- `Ctrl+Tab` 循环切换；`Ctrl+W` 关闭当前标签；关闭最后一个标签显示欢迎页（§5.1）。
- 未保存标签关闭时提示"保存/不保存/取消"。

**单文件时的文件名呈现（关键细节）：**
- **窗口标题（OS 任务栏 / Alt+Tab）始终显示文件名**，所有模式、所有标题栏样式下均有效。
- 自定义标题栏（样式 B）时，文件名显示在标题栏内（居中/居左可配置），未保存时显示 `●` 标记——对标 Typora（即 TB-03"是否显示文档名"配置项，默认显示）。
- 原生标题栏（样式 A）时由系统窗口标题承担，无需额外处理。
- 无边框沉浸模式时标题栏隐藏，文件名不占空间；状态栏左侧可显示完整路径（可开关，对标 VS Code 面包屑）。
- 进入沉浸模式（E-06）时标签栏一并隐藏，退出后按"自动"模式逻辑恢复。

**多窗口：**
- 支持多个窗口（`Ctrl+Shift+N` 新建窗口），窗口间互不影响、各自独立标签集合。
- 多窗口适合：对比写作、多主题同时预览（P2 预留拖标签到新窗口）。

#### 3.5.3 设置与数据存储

| 项 | 说明 |
| --- | --- |
| 设置入口 | 命令面板（`Ctrl+Shift+P`）+ 设置界面（图形化） |
| 存储位置 | 遵循各平台应用数据目录规范，由 Tauri path API（`app_config_dir` 等）解析，应用内目录结构三平台统一（见下） |
| 工作区设置 | 支持项目级 `.mdeditor/` 配置（P2 预留） |
| 主题数据 | 主题以**包目录**存放于 `themes/` 子目录（一主题一文件夹），便于分享与备份 |

**配置目录（平台映射）：**

| 平台 | 配置 + 用户数据 | 缓存（可清理） |
| --- | --- | --- |
| Windows | `%APPDATA%\com.mdeditor.desktop\` | `%LOCALAPPDATA%\com.mdeditor.desktop\` |
| macOS | `~/Library/Application Support/com.mdeditor.desktop/` | `~/Library/Caches/com.mdeditor.desktop/` |
| Linux | `$XDG_CONFIG_HOME/com.mdeditor.desktop/`（默认 `~/.config/com.mdeditor.desktop/`） | `$XDG_CACHE_HOME/com.mdeditor.desktop/`（默认 `~/.cache/com.mdeditor.desktop/`） |

**应用内目录结构（三平台统一，全部位于数据根目录 `MDEDITOR_HOME` 下）：**

```
com.mdeditor.desktop/            # 数据根目录（默认；可由 MDEDITOR_HOME 覆盖）
├── settings.json        # 应用设置（主题选择、布局记忆、同步配置[不含凭据]）
├── keybindings.json     # 快捷键自定义（P1，K-01～K-25 重绑定）
├── recent.json          # 最近文件列表（S-02）
├── themes/              # 用户主题包：一主题一文件夹（T-04，见 3.4.5）
│   └── my-theme/
├── workspaces/          # 工作区状态（打开的文件夹、标签页布局）
├── drafts/              # 自动保存草稿（E-23 崩溃恢复）
├── cache/               # 缓存（渲染缓存、临时文件，可随时清理）
└── logs/                # 日志（排查用）
```

**存储原则：**
1. **凭据不入配置**：服务器密码等敏感信息存系统密钥链（SY-06），配置中仅存引用键。
2. **可迁移**：整个数据根目录打包即迁移到另一台设备（含设置、主题、草稿）。
3. **逻辑分离**：统一根目录下按子目录区分职责——`cache/`、`logs/` 可随时删除或备份时排除，其余为需备份的用户数据。
4. **设置文件为 JSON**（VS Code 同款做法）——与"主题用纯 CSS"不冲突：主题是样式（CSS），应用配置是机器可读数据（JSON）。

**环境变量覆盖（可选，改变数据根目录）：**

| 环境变量 | 作用 | 说明 |
| --- | --- | --- |
| `MDEDITOR_HOME` | 覆盖**数据根目录** | 配置、主题、缓存、日志、草稿全部随之一并迁移到该目录 |

- **优先级**：环境变量 > 平台默认路径；未设置时使用上表平台默认目录。
- **取值规则**：需为绝对路径；支持可执行文件旁的相对路径（**便携模式**：解压即用、不写系统目录）。
- **容错**：目录不存在时自动创建；**不可写时回退默认目录并在启动日志/设置页提示**，不阻断启动。
- **平台注意**：Windows 用户级环境变量对 GUI 应用可见；**macOS 从 Finder/Launchpad 启动的应用不继承 shell 环境变量**，需通过 `launchctl setenv` 或启动配置（`.plist`）设置；Linux 从终端启动可见，从桌面启动取决于桌面环境（可在 `.desktop` 文件 Environment 中设置）。
- **典型用途**：便携版、多套配置切换（工作/个人）、CI 与测试隔离。
- **可查性**：设置界面"关于/存储"页**只读展示当前生效的目录路径**，便于用户排查。

#### 3.5.5 云同步（自带服务器，BYOS）

> **需求**：不提供官方云端服务，但支持用户接入**自己拥有的服务器**进行文件同步（BYOS，Bring Your Own Server）。**服务端无需安装专用软件**——使用标准的 WebDAV 协议即可，因此 Nextcloud、群晖、坚果云、自建 nginx 等均可作为同步后端。

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| SY-01 | WebDAV 同步 | P1 | 对接用户自建/自有 WebDAV 服务器（Nextcloud、群晖、坚果云、自建等），支持目录级同步（工作区/文件夹 ↔ 服务器路径） |
| SY-02 | 手动/自动同步 | P1 | 手动触发同步 + 可选定时自动同步（间隔可配置，默认关闭自动，避免无感占用网络） |
| SY-03 | 冲突检测与处理 | P1 | 检测两端同时修改的冲突：提示"保留本地 / 保留远端 / 另存冲突副本"，**绝不静默覆盖** |
| SY-04 | 同步状态指示 | P1 | 状态栏/文件树图标显示：已同步 / 同步中 / 冲突 / 离线未同步 |
| SY-10 | 离线容错 | P1 | 同步失败进入重试队列，网络恢复后自动补传；本地修改始终不丢失 |
| SY-06 | 凭据安全存储 | P1 | 服务器凭据存入**系统密钥链**（Windows 凭据管理器 / macOS Keychain / Linux Secret Service），不落明文配置 |
| SY-05 | 多服务器配置 | P2 | 支持多套同步配置（不同服务器/不同目录/不同工作区） |
| SY-07 | SFTP 同步 | P2 | 支持 SFTP/SSH 服务器（程序员向自己的服务器同步） |
| SY-08 | Git 仓库同步 | P2 | 可选：以 Git 仓库为同步介质，推送到用户自己的 Git 服务器/私有仓库 |
| SY-09 | 自定义同步命令 | P2 | 可配置外部命令（如 rclone）作为同步后端，最大化开放性 |

**同步行为细则：**

- **同步粒度**：以"工作区/文件夹"为单位映射到服务器目录；支持排除规则（如忽略 `.git/`、`node_modules/`、临时文件）。
- **传输安全**：支持 HTTPS（TLS），拒绝明文密码传输；同步前对本地文件做哈希校验，避免重复上传。
- **同步时机**：保存文件后延迟去抖触发（如 2s）；自动模式按配置间隔轮询服务器变更并拉取。
- **配置管理**：同步配置存于用户设置（§3.5.3），凭据不入配置、只存密钥链。
- **状态可查**：提供同步日志（最近 N 条），便于排查网络/权限问题。

> **实现说明**：WebDAV/SFTP 客户端在 Rust 侧实现（`rust-webdav` / `ssh2` crate）并通过 Tauri command 暴露给前端；`packages/*` 保持零 Tauri 依赖，同步逻辑放主应用 Rust 层（`src-tauri/`）或独立 `packages/md-sync`（纯协议客户端，供复用）。

#### 3.5.6 多语言（i18n）

> **需求**：界面支持多语言，内置简体中文与英文，可跟随系统语言自动切换，并支持外部语言包扩展。**用户文档内容语言与界面语言相互独立**——i18n 只作用于应用 UI 文案，不触碰文档内容。

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| I-01 | 界面语言切换 | P1 | 设置中手动选择界面语言，**即时生效、无需重启** |
| I-02 | 内置语言 | P1 | 至少内置简体中文（zh-CN）+ English（en-US）；缺省回退 en-US |
| I-03 | 跟随系统 | P1 | 默认"跟随系统语言"自动选择（可改为手动固定） |
| I-04 | 语言包机制 | P2 | 外部语言包（社区翻译）放入 `locales/` 目录即被识别；格式 JSON，key 与内置一致 |
| I-05 | 文案抽取规范 | P0（工程约束） | 所有 UI 文案必须走 i18n key（`t('menu.file.new')`），禁止硬编码字符串 |
| I-06 | 日期/时间本地化 | P2 | 最近文件时间、字数统计等按所选语言习惯格式化 |
| I-07 | 拼写检查联动 | P2 | 拼写检查（E-24）默认语言跟随界面语言，可单独覆盖 |
| I-08 | RTL 语言支持 | P2 | 预留从右到左排版（阿拉伯语/希伯来语等），本期不做 |

**语言包结构：**

```
src/locales/
├── zh-CN.json        # 内置：简体中文
├── en-US.json        # 内置：英文（缺省回退语言）
└── <其他>.json       # 用户/社区放置的外部语言包（I-04）
```

**语言选择优先级**：手动选择 > 系统语言 > en-US 缺省。

**实现约定：**
- 语言包采用 JSON（与主题用纯 CSS 不冲突：翻译是文本数据、主题是样式）。
- 前端框架：`i18next` / `react-i18next`（或等价方案）；语言包 key 按模块分层（`menu.*`、`activity.*`、`editor.*`、`settings.*`、`welcome.*` 等）。
- **库内文案约束**（对齐 §6.1）：`packages/*` 不绑定 i18n 框架——库内需翻译的文案（如编辑器 placeholder）通过选项注入翻译函数或由调用方传入，保持库的框架无关性。
- 设置项"语言"随 `settings.json` 持久化（§3.5.3）；语言包目录可被环境变量覆盖的配置目录引用（§3.5.3）。

## 4. 非功能需求

### 4.1 跨平台（核心要求）

| 平台 | 要求 | 实现要点（Tauri 2） |
| --- | --- | --- |
| Windows | Windows 10/11（x64、arm64 优先 x64）；标题栏/无边框需处理 DPI 缩放、Aero Snap、高对比度模式 | 原生标题栏改色：Rust 调 `DwmSetWindowAttribute`（Win11 22H2+）；Snap Layout 用 `decorum`/`decoration` 插件；Mica/Acrylic 用 `window-vibrancy`；DPI 由 Tauri 自动处理，自绘标题栏需配合 CSS 缩放适配 |
| macOS | macOS 12+（Intel 与 Apple Silicon）；遵循 HIG（Traffic Light、菜单栏、全屏手势、触控板滚动） | 红绿灯用官方 `titleBarStyle: Overlay` 或 `decorum` 插件；无边框时需预留左侧红绿灯空间；全屏手势与菜单栏由系统提供 |
| Linux | 主流发行版（Ubuntu/Fedora/Arch 等）；兼容 GNOME / KDE / X11 / Wayland；提供 AppImage/deb/rpm 等打包 | 无边框在 Wayland 下兼容性差（GNOME 需要 `gtk_header_bar` 策略或装饰协商），必须提供"原生标题栏"回退选项；X11 下自绘标题栏可行；各桌面环境的阴影/圆角支持不一 |

- **一致性原则**：同一功能在三端行为一致；平台差异（如窗口控制按钮位置）遵循各平台惯例。
- **打包分发**：提供各平台安装包（Windows NSIS/msi、macOS dmg、Linux AppImage/deb/rpm）。

### 4.2 性能

| 指标 | 要求 |
| --- | --- |
| 启动时间 | 冷启动 ≤ 2s（主流配置） |
| 大文档 | 10 万字文档滚动/输入无明显卡顿（≥ 30 FPS） |
| 内存 | 空闲 ≤ 300MB；单文档编辑 ≤ 500MB |
| 渲染 | 输入到渲染延迟 ≤ 50ms |

### 4.3 稳定性与数据安全

- 自动保存 + 崩溃恢复（临时文件 `.md~` 机制）。
- 文件写入原子化，避免中途断电损坏。
- 大文件（≥ 10MB）给予明确提示并采用降级策略（如懒渲染）。

### 4.4 无障碍（可访问性）

- 支持系统缩放字体与 DPI。
- 关键操作键盘可达；焦点指示清晰。
- 颜色对比度满足 WCAG AA（默认主题）。

### 4.5 隐私

- 全部本地运行，无遥测（或默认关闭、可明确选择加入）。
- 不收集文档内容；崩溃日志仅含必要技术信息。
- **云同步为用户主动配置**：数据仅发往用户自己填写的服务器地址；凭据存系统密钥链，不落明文（§3.5.5）。

### 4.6 可扩展性（预留）

- 插件系统预留：活动栏扩展点、命令注册、主题贡献点（contribution points，对标 VS Code）。
- 自定义 Markdown 渲染扩展（如自定义容器、提示框）——通过 `md-core` 的插件注册机制实现（见 §6.1）。
- Markdown 能力独立封装为库（`packages/*`），第三方插件可直接复用（见 §6.1.3）。

## 6. 技术选型建议（供评审，非最终决策）

| 方向 | 方案 | 理由 |
| --- | --- | --- |
| 桌面框架 | **Tauri 2**（已定） | 跨平台、安装包小（<10MB）、Rust 内核性能好；v2 已稳定，窗口定制生态成熟 |
| 编辑器内核 | CodeMirror 6 / Monaco / ProseMirror | WYSIWYG 推荐 ProseMirror 或 CodeMirror 6 扩展；源码高亮可用 Monaco |
| 渲染 | markdown-it + 插件（KaTeX、Mermaid、highlight.js） | 生态成熟、性能好 |
| UI | React + TypeScript | 主题系统需要 CSS 变量体系支撑 |
| 主题方案 | **纯 CSS 主题文件**（CSS 自定义属性 = 变量，`data-theme` 切换） | 满足 3.4 全部需求；无 JSON 映射层，导入即生效 |

| 平台 | 方案 | 理由 |
| --- | --- | --- |
| macOS | `muda`（Tauri 官方菜单库）→ 原生 NSMenu，进系统顶部菜单栏 | 用户习惯；系统免费提供快捷键声明（Cmd+C/V 等）、VoiceOver 无障碍、随应用切换自动更新 |

### 6.1 代码结构：Markdown 能力独立封装为库（架构决策）

> **架构原则**：MdEditor 采用 Monorepo 结构，**所有 Markdown 相关能力（解析、渲染、编辑内核、导出）封装为独立库，放在单独的文件夹（`packages/`）中**，主应用（Tauri 壳）只负责窗口、文件树、主题、设置与界面编排，通过调用这些库完成 Markdown 功能。库与壳之间单向依赖、通过对外 API 解耦。

#### 6.1.1 目录结构（npm workspaces）

```
MdEditor/                       # Tauri 2 主应用（根目录）+ Monorepo
├── src/                       # 界面：活动栏、侧边栏、编辑区、主题 UI
├── src-tauri/                 # Rust 壳：窗口、无边框、系统集成
├── public/                    # 静态资源（应用图标等）
├── index.html                 # 前端入口
├── vite.config.ts / tsconfig.json
├── packages/                  # Markdown 能力独立库（workspaces）
│   ├── md-core/               # 【核心库】Markdown 解析 + 渲染（纯函数，无 UI）
│   │   ├── src/
│   │   │   ├── parse.ts       # markdown → AST
│   │   │   ├── render.ts      # AST/markdown → HTML
│   │   │   └── plugins/       # KaTeX / Mermaid / highlight 等扩展
│   │   └── package.json
│   ├── md-editor/             # 【编辑器库】编辑内核封装（WYSIWYG / 源码模式）
│   │   ├── src/
│   │   │   ├── Editor.ts      # 编辑器组件与实例 API
│   │   │   ├── source/        # 源码模式（CodeMirror 6）
│   │   │   └── wysiwyg/       # 所见即所得模式（ProseMirror）
│   │   └── package.json
│   ├── md-export/             # 【导出库】HTML / PDF / 图片导出（P1）
│   │   ├── src/
│   │   │   └── index.ts
│   │   └── package.json
│   └── md-sync/               # 【同步库，可选】WebDAV/SFTP 纯协议客户端（P1，供主应用与插件复用）
│       ├── src/
│       │   └── index.ts
│       └── package.json
├── docs/
└── package.json               # 根配置（workspaces: packages/*，同时是 Tauri 主应用）
```

#### 6.1.2 库的边界与对外 API（草案）

| 库 | 职责 | 对外 API（示例） | 依赖 |
| --- | --- | --- | --- |
| `md-core` | 解析 + 渲染，纯逻辑无 UI | `parse(md): Ast`、`render(md|Ast, options): Html`、`registerPlugin()` | 无（仅 markdown-it 生态） |
| `md-editor` | 编辑器内核封装，支持双模式 | `createEditor(el, options): EditorInstance`（含 `getValue/setValue/onChange` 等） | 依赖 `md-core` |
| `md-export` | 导出 HTML/PDF/图片 | `exportHtml(md, theme)`、`exportPdf(md, options)` | 依赖 `md-core` |

**设计约束：**

1. **零 Tauri 依赖**：`packages/*` 全部为纯前端/纯 JS 库，不 import Tauri API，保证可在浏览器中独立运行与测试。
2. **零 UI 框架依赖**：`md-core` 不依赖 React/Vue；`md-editor` 对外暴露框架无关的实例 API，React 壳仅做薄封装（未来若换 UI 框架或接插件系统无需重写核心）。
3. **单向依赖**：主应用（根目录 `src/`）→ `packages/*`；`md-editor → md-core`；禁止反向依赖。
4. **主题联动**：主题系统通过 CSS 变量作用于编辑器渲染层，`md-core` 输出带 `class` 的语义化 HTML，样式由主题层注入。
5. **独立测试与版本**：每个库有独立测试（vitest）与版本号，后续可独立发布到 npm。

#### 6.1.3 独立封装带来的收益

- **可复用**：未来 Web 版、CLI 工具、插件市场可直接复用这些库。
- **可测试**：纯库单元测试成本低，不依赖窗口环境。
- **解耦**：编辑器内核更换（如 CodeMirror ↔ ProseMirror）只影响 `md-editor` 内部，对外 API 不变。
- **插件生态基础**：第三方插件通过 `md-core` 的注册机制与 `md-editor` 的扩展点接入（对齐 §4.6）。

## 10. 验收标准（示例）

1. 在 Windows/macOS/Linux 三平台完成安装并启动，核心功能一致。
2. 输入 Markdown 即实时渲染，光标跟随无异常；10 万字文档流畅编辑。
3. 可切换浅/深主题；可自定义标题栏颜色与样式；可开启无边框窗口并正常拖拽、最小化、最大化、关闭。
4. 无边框模式在 Windows 支持贴边分屏，在 macOS 保留 Traffic Light 与全屏手势。
5. 主题文件可导出并在另一台设备导入生效。
6. 自动保存开启后强制退出程序，重启可恢复未保存内容。

## 11. 术语表（Glossary）

| 术语 | 说明 |
| --- | --- |
| WYSIWYG | What You See Is What You Get，所见即所得：输入即按最终样式渲染 |
| GFM | GitHub Flavored Markdown，GitHub 扩展的 Markdown 语法规范（任务列表、表格、删除线等） |
| 活动栏 | Activity Bar，最左侧竖条图标栏，用于切换侧边栏面板（对标 VS Code） |
| 侧边栏 | Sidebar，左侧功能面板区（文件树/搜索/大纲等），可收起、可调宽 |
| 状态栏 | Status Bar，窗口底部信息栏（行列号、字数、主题入口等） |
| 无边框窗口 | Frameless Window，关闭系统原生装饰（标题栏/边框）的窗口，由应用自绘 |
| Snap Layout | Windows 11 的窗口贴靠布局：拖拽窗口到屏幕边缘或悬停标题栏按钮时显示布局面板 |
| Aero Snap | Windows 的窗口贴边分屏（拖拽到屏幕边缘自动半屏/四分之一屏） |
| Mica / Acrylic | Windows 11 窗口材质效果（背景模糊/亚克力），常用于沉浸式标题栏 |
| Traffic Light | macOS 窗口左上角红/黄/绿三个控制按钮 |
| Wayland / X11 | Linux 图形显示服务器协议（X11 为传统协议，Wayland 为新一代） |
| Monorepo | 单一代码仓库管理多个包（应用 + 库）的结构，配合 npm workspaces 使用 |
| AST | Abstract Syntax Tree，抽象语法树：Markdown 解析后的结构化中间表示 |
| 命令面板 | 输入命令快速执行功能的弹出面板（对标 VS Code 的 Ctrl+Shift+P） |
| DPI | 每英寸点数，影响界面缩放；高 DPI 显示器需适配 |
| WCAG | Web Content Accessibility Guidelines，无障碍内容指南（AA 为常见达标级别） |
| WebDAV | 基于 HTTP 的文件操作协议（RFC 4918），Nextcloud、群晖、坚果云、自建 nginx 等均支持，是 BYOS 同步的服务端标准 |
| SFTP | SSH File Transfer Protocol，基于 SSH 的安全文件传输协议，常用于向自己的服务器同步 |
| 系统密钥链 | 操作系统提供的凭据安全存储（Windows 凭据管理器 / macOS Keychain / Linux Secret Service） |
| BYOS | Bring Your Own Server，自带服务器：用户使用自己拥有的服务器进行数据同步，官方不提供云端 |
| i18n | Internationalization，国际化：应用 UI 文案多语言支持（与文档内容语言相互独立） |
| locale | 语言区域标识（如 zh-CN、en-US），决定界面语言与日期等格式 |
| RTL | Right-To-Left，从右到左排版（阿拉伯语、希伯来语等） |
